# Glossary

Every term used in the workflow, the [playbook](./playbook/c-to-rust-migration-playbook.md), or the [run reports](./runs/README.md) — grouped by topic, terse on purpose.

## Agentic / agent-driven

- *Agentic CLI* — a command-line AI tool that plans multi-step work, edits files, runs commands, reads exit codes, and iterates without per-step human approval. Used here: **Claude Code**, **Codex**.
- *Agentic workflow* — a procedure designed for an agentic CLI to execute end to end (the [playbook](./playbook/c-to-rust-migration-playbook.md) is the one used here).

## The four crates of every migration

- *`<lib>-rs`* — the **safe core**: a from-scratch reimplementation of the C algorithm in idiomatic Rust, with `#![forbid(unsafe_code)]` and zero runtime dependencies. The thing a downstream user actually depends on.
- *`<lib>-sys`* — **inbound FFI**: Rust bindings to the original C, generated by `bindgen` and compiled by the `cc` crate. Used at test time only — it is the *ground truth* the safe core is compared against.
- *`<lib>-cabi`* — **outbound FFI**: a stable C ABI exposing the safe core back to C callers (`extern "C"`, `#[repr(C)]`, `cbindgen`-generated header, `*_rs_free`).
- *`<lib>-diff`* — the **differential oracle**: shared input model + `check_against_reference()` asserting the chosen equivalence relation across many inputs (proptest + reused by fuzz).

## FFI mechanics

- *FFI (Foreign Function Interface)* — the mechanism for code in one language to call compiled code in another across a stable ABI.
- *ABI (Application Binary Interface)* — the binary calling/layout convention two compiled modules must agree on.
- *`extern "C"`* — Rust attribute exposing a function with C calling convention so C can call it.
- *`#[repr(C)]`* — Rust attribute making a struct's field layout match the C ABI.
- *`bindgen`* — generates Rust bindings from a C header. Inbound direction (use C from Rust).
- *`cbindgen`* — generates a C header from a Rust crate's `extern "C"` surface. Outbound direction (use Rust from C).
- *Allocator symmetry* — buffers must be freed by the same allocator that allocated them. C-`malloc`'d pointers must be `libc::free`'d; Rust-`Box::into_raw`'d pointers must be `Box::from_raw`'d. Mixing is undefined behavior.
- *`*_rs_free`* — the outbound-side free function this workflow ships so C callers can release buffers returned from the Rust port using Rust's allocator.
- *RAII (Resource Acquisition Is Initialization)* — Rust pattern where a type's `Drop` impl releases the resource it owns; here used to wrap C-allocated handles so they're freed by the matching C destructor automatically.

## Safety

- *`#![forbid(unsafe_code)]`* — crate-level attribute that makes the compiler reject any `unsafe` block in the crate. Compile-enforced, not a convention.
- *`unsafe` block / safety contract* — Rust language feature for operations the compiler can't check (raw-pointer deref, FFI calls). Every block in this workflow carries a comment stating the invariants the caller must uphold.
- *Total function* — a function that returns for every input rather than panicking or invoking UB. Decoders here are total on hostile input (return `Result`, bounds-check every read).
- *Vendoring* — copying the upstream C/C++ source into this repo verbatim at a pinned commit (`vendor/<lib>/`) so the build doesn't depend on the network and the reference can't drift.

## Verification (the equivalence proof)

- *Differential testing / differential oracle* — run the Rust port and the C reference on the same input and assert their outputs satisfy the chosen relation.
- *Equivalence relation / `oracle_relation`* — what "equivalent" means for this library:
  - *`byte_exact`* — outputs are byte-for-byte identical. Used for these codecs and hashers.
  - *`behavioral`* — same return code, same out-params/buffer, same error signal. Used when the output isn't uniquely defined.
  - *`model_based`* — drive both implementations with the same operation sequence and compare observable state at each step. Used for stateful APIs.
- *Property-based testing / `proptest`* — generate hundreds–thousands of inputs from a strategy and check that an invariant (a *property*) holds on each. Cases shrink to a minimal counterexample on failure.
- *Golden vectors* — inputs paired with the reference's exact output, checked into the repo so the safe core can be tested with **no C present**.
- *Fuzzing / `cargo-fuzz` / libFuzzer* — feed mutated bytes into a target until something crashes. `cargo-fuzz` is the Rust frontend; libFuzzer is the underlying engine. Needs nightly Rust.
- *Differential fuzzing* — fuzz target whose property is *Rust and C agree*, not just *doesn't crash*. This workflow ships both kinds: `differential` and `no_panic`.
- *Round-trip property* — `decode(encode(x)) == x` for every valid `x`. A self-contained correctness check that needs no external oracle.

## Benchmarking

- *`criterion`* — statistical microbenchmark harness for Rust. Reports throughput with confidence intervals.
- *`hyperfine`* — whole-process benchmark tool that runs two CLIs many times and reports the relative speed with noise bounds. Used here to race a C binary built with `-O3` against a Rust binary built with `--release` on identical work + a printed checksum (defeats dead-code elimination).
- *`-O3` / `--release`* — peak-optimization flags for `cc` and `cargo` respectively. Both benchmarks use these to be a fair comparison.

## Reproducibility

- *Pinned upstream* — a specific commit SHA or release tag (e.g. `97bacc86…0b9`, `v0.8.3`) recorded in the config block, vendored into `vendor/<lib>/`. Not a moving branch.
- *`Cargo.lock`* — exact dep-graph snapshot. Committed for libraries here because reproducibility matters more than minor-version drift.
- *Config block* — the YAML at the top of each `*-task.md`. Everything library-specific about a run lives there; the rest of the playbook is identical across libraries.

## Libraries used as examples

- *QOI* — "Quite OK Image" codec. ~300 LOC C, single-header, MIT, deterministic spec — clean target for `byte_exact`.
- *xxHash* — fast non-cryptographic hash. The one-shot `XXH32` / `XXH64` APIs are ported (~250 LOC, BSD-2-Clause). Pure functions returning a scalar by value, so nothing crosses the FFI boundary by pointer.
- *Ring Buffer* — small stateful C queue API with caller-provided storage. Used for the `model_based` run.
- *RE2* — Google's C++ regular-expression engine. Used here as an ownership/RAII interop run, not as a full regex-engine rewrite.
- *Kani* — Rust model checker used here for bounded proof-smoke harnesses over safe core invariants.
